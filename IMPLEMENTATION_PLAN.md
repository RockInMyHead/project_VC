# Что осталось до приёмки «Бок о бок»

Основа: ТЗ версии 1.1 от 28 августа 2026 г. и текущий код проекта на 25 сентября 2026 г. Платежи и инвестиционные транзакции в ТЗ не входят.

## Уже реализовано

- Четыре роли с серверной проверкой прав; заявки основателей, создание инвесторов и сотрудников фонда администратором.
- Карточки проектов, версии деревьев, этапы и материалы; отправка на проверку, публикация и возврат с замечанием.
- Просмотр опубликованных проектов инвестором, сравнение без рейтинга, вопросы и ответы, уведомления в кабинете, история и аудит.
- Личный чат как дополнительная функция. Локальный вход по паролю временно работает без SMS; при внешнем запуске сервер требует SMS-2FA.
- Сотрудник фонда может создать проект для действующего основателя; владелец и назначенный сотрудник управляют доступом команды к рабочей версии.
- Caddy передаёт адрес клиента серверу из своего TCP-соединения, сервер принимает заголовок только от внутреннего прокси. Мобильная навигация кабинета остаётся доступной.
- В дереве узлы имеют понятные подписи для экранного диктора и сохраняют фокус после выбора; календарь и ширина окна линзы управляются клавиатурой.
- Черновики проекта, карточки, события, вопроса и сообщения сохраняются в пределах вкладки вместе с ключом повторной отправки; повторный запрос не создаёт дубль сообщения.
- 36 автоматических тестов проходят, в том числе сохранение разветвлённого дерева из 100 событий через API, ограничение ленты изменений доступными основателю проектами и фильтрация/пагинация администраторского аудита. Это подтверждает проверенные сценарии кода, а не приёмку на реальном сервере.
- Скрипт резервного копирования проверяет целостность SQLite до публикации файла; локально проверены успешное восстановление и отказ при повреждённой копии.

## P0 — обязательное до рабочего запуска

1. **Завершить развёртывание.** Решить, переносить ли текущую локальную БД: подготовленный архив проекта её не содержит. Передать сборку на Cloud.ru, настроить домен и HTTPS, проверить DNS, доступность API и пользовательские сценарии. Текущая ВМ сообщает о диске 14,66 ГБ; ТЗ указывает 120 ГБ SSD, поэтому сверить и при необходимости увеличить диск, CPU и RAM.
2. **Включить реальную SMS-2FA.** Настроить ключ провайдера, номера пользователей, доставку, ограничения попыток и сценарий недоступности SMS. Без `SMS_RU_API_ID` вход на внешнем сервере сейчас не завершится. Не использовать публичный HTTP для ввода паролей.
3. **Создать начального администратора и реальные учётные записи.** Проверить одобрение основателя, создание инвестора и сотрудника фонда, назначение сотрудника, блокировку доступа и выход из системы на развёрнутом сайте.
4. **Создание проекта сотрудником фонда — реализовано локально.** Проверить на развёрнутом сайте выбор основателя и дальнейшую модерацию.
5. **Настроить резервное копирование.** Включить ежедневный таймер, проверить восстановление на отдельной БД и копирование резервных файлов за пределы ВМ. Один архив на том же диске недостаточен.
6. **Учёт IP за Caddy — реализовано локально.** После развёртывания проверить, что аудит и лимит входов разделяют разных клиентов.

## P1 — завершение сценариев и качества MVP

7. **Управление командой — реализовано локально.** Владелец и сотрудник фонда добавляют, меняют права и удаляют участников; сервер проверяет доступ, пишет историю и уведомляет участника. Проверить в браузере четырёх ролей после развёртывания.
8. **Довести дерево и линзу времени по макетам.** Клавиатурное управление узлами и линзой, а также мобильная навигация добавлены. API проверен на разветвлённом дереве из 100 событий. Осталось сверить экран с утверждённым вариантом Figma: ветви и линии переходов, карточку события, УГТ, масштаб времени и плотность узлов; проверить большой граф в браузере.
   Отдельно зафиксировать смысл процента готовности и перехода между уровнями УГТ: сейчас эти значения вводятся вручную и не выводятся из подтверждающих материалов.
9. **Проверить устойчивость форм и сети.** Черновики проекта, карточки, этапа, вопроса и сообщения сохраняются в пределах вкладки; повторная отправка защищена ключом запроса. Осталось пройти проверки при реальном обрыве сети и уточнить состояния отправки.
10. **Провести приёмочные проверки четырёх ролей.** На desktop, tablet и mobile пройти полный цикл: создание → правка → проверка → публикация → просмотр инвестором → вопрос → ответ → уведомление → новая версия. Проверить запреты чужих проектов, приватность черновика и корректность истории.
11. **Измерить производительность.** На целевой ВМ проверить p95 типовых API-запросов до 200 мс при согласованной штатной нагрузке, время открытия большого дерева и расход памяти/диска. Оптимизировать только выявленные узкие места.
    Локальный синтетический замер на 100 проектах и 3 этапах в каждом показал p95 около 1,3 мс для списка и 0,4 мс для карточки при прямом вызове Python. Он не учитывает HTTP, сеть, браузер и конкурирующие запросы и не заменяет замер на ВМ.

## P2 — после приёмки MVP

- Автоматические напоминания, если активный проект не обновлялся неделю: в ТЗ дата актуализации обязательна, автоматизация контроля отложена.
- Внешние уведомления, восстановление пароля пользователем, крупные файлы через объектное хранилище.
- PostgreSQL и общее файловое хранилище перед запуском нескольких экземпляров приложения; текущая SQLite-конфигурация рассчитана на один экземпляр.
- Денежные инвестиции и платежи — только по отдельному ТЗ.

# Архитектура и API

## Компоненты

- `app.js`: вход, рабочий кабинет, создание проектов, личные сообщения, отдельные страницы уведомлений и изменений основателя.
- `focus.js`: интерактивное дерево, УГТ и временной фокус.
- `workflow-ui.js`: формы карточки/этапов, проверки, материалов, вопросов, сравнения и уведомлений.
- `admin.js`: пользователи, регистрации, назначения сотрудников фонда и аудит.
- `backend/server.py`: HTTP, сессии, маршруты, доставка статических файлов по разрешённому списку.
- `backend/workflow.py`: правила ролей, команды, транзакции публикаций и история.
- `backend/sms.py`: SMS.RU; без настроенного провайдера вход сообщает об отсутствии доставки и не выдаёт сессию.
- `backend/db.py`, `db/migrations`: SQLite WAL, внешние ключи, индексы, транзакционные миграции.

## Данные и инварианты

Пользователь имеет одну из четырёх ролей. Основатель управляет своими проектами и составом команды. Сотрудник фонда управляет назначенными ему проектами и может создать проект для действующего основателя; такой проект сразу закрепляется за ним. Участник команды с доступом `researcher` редактирует рабочую версию, с доступом `viewer` только просматривает её. Администратор назначает сотрудника через админку. Инвестору доступны все опубликованные проекты (активные, приостановленные, завершённые).

Проект имеет версии дерева. Рабочая версия содержит снимок карточки `card_json` и этапы со ссылками на родителей. `draft → in_review → published/rejected`. Редактирование на проверке запрещено. После публикации или возврата создаётся новая рабочая версия с копией этапов и материалов. Инвестор продолжает видеть последнюю опубликованную версию. Публикация атомарно обновляет карточку и дату актуализации. При удалении этапа дети переходят к его родителю, циклы запрещены.

Материалы до 500 КБ сохраняются в SQLite в base64 с размером и SHA-256. Это ограничение текущего MVP: для крупных файлов нужен отдельный адаптер объектного хранилища. Скачивание требует доступа к версии; публичных адресов файлов нет.

Вопрос инвестора виден автору, назначенному сотруднику фонда и администратору. События записываются в аудит; история проекта содержит автора, время и значения до/после изменений. Инвестор видит только историю публикаций. Уведомления об изменениях рабочих статусов получает команда, о публикации — команда и подписчики; неопубликованные данные инвестору не отправляются.

## HTTP

Все запросы/ответы JSON. Защищённые маршруты требуют `Authorization: Bearer <token>`. Ошибки: `{error, message}` с русским `message`. Коды: 401 — нет сессии; 403/404 — нет прав/объекта; 409 — конфликт/устаревшая ревизия; 422 — данные; 429 — лимит входов; 503 — SMS недоступен.

| --- | --- |
| POST /api/registration-requests | Заявка основателя: full_name, email, organization |

Команды проекта и админки, создание проекта и сообщение принимают `request_key`. При потере ответа повторите **тот же ключ и те же данные**: операция не повторится. Другие данные с тем же ключом дадут 409. Изменения дерева принимают `revision` из ответа карточки; при несовпадении нужно обновить данные. UI передаёт ревизию автоматически. Новый проект сохраняет незавершённую форму в sessionStorage текущей вкладки; ошибки не очищают формы.

## Безопасность и ограничения

Пароли PBKDF2-SHA256, токены сессий и OTP хранятся хешированными. OTP живёт 5 минут, 3 попытки, однократное использование. Сессия 12 часов, блокировка пользователя немедленно запрещает API-доступ. Изменение доступа отзывает сессии. Запросы входа ограничены 20 попытками за 15 минут на IP. При обратном прокси нужен дополнительный лимит по клиентскому IP на уровне инфраструктуры (приложение не доверяет произвольному X-Forwarded-For).

Bearer-токен хранится в localStorage. Для отдельного production-проекта можно перейти на HttpOnly-cookie с CSRF-защитой. CSP запрещает встроенные скрипты и внешние подключения; пользовательские тексты вставляются через textContent.

Горизонтальный запуск нескольких экземпляров с общей SQLite не поддерживается. Границы модулей позволяют заменить SQLite на PostgreSQL и вынести материалы в объектное хранилище, но это отдельная инфраструктурная миграция. Целевой p95 <=200 мс проверяется нагрузочным тестом на целевой инфраструктуре, не считается подтверждённым одними unit-тестами.
